# 叫号条（Callslip）

银行网点柜面叫号：取号入队 → 叫号推进 → 过号回收/重叫 → 当日队列封口。

- 前端 http://127.0.0.1:6400
- API http://127.0.0.1:11400
- `docker compose up -d --build`

## 跨种类选号次序口径（全局唯一）

本系统全局只贯彻 **架构一「全局取号时刻先进先出」**：

- 叫号谓词：窗口**可办种类交集内**，`状态=等候` 中按 `(取号时刻, 号牌id)` 升序叫最早者；
  并列取号时刻以号牌 id 破（id 即真实先后）。
- 不得因种类偏好跳号：叫号入口**没有**按次种类下拉，种类过滤唯一来源是
  **窗口可办种类表**（窗口页勾选维护，`POST /api/窗口/{id}/可办种类`）。
- 绝不可叫到可办种类外的号；同窗反复叫号也不会只吃一种类（FIFO 天然不积压他类）。
- 可重放：叫号事件记录**种类字段**与选号快照（可办种类、候选数、规则），
  `GET /api/叫号流水/校验` 按事件流重放谓词逐条核对，冲突即未闭合。
- **假次序收口（唯一口径，绝不分叉）**：`app/services/order_audit.py` 是全局唯一
  判定「这次叫号是否按序」的地方，做三件事——次序（叫到可办交集内 `(取号时刻,号牌id)`
  最早者）、覆盖（叫到号在快照可办种类内）、状态同命运（审计末事件与号牌状态、窗口占号一致）。
  所有写口（取号/叫号/过号/重叫/办结/作废）在 `BEGIN IMMEDIATE` + `SAVEPOINT` 内先写后
  重放整日事件流；**不一致则整笔回滚并返回 409**，绝不出现「回执绿而次序证据撒谎」或
  「只改墙高亮样式」的旁路。墙高亮、序号页「可叫」、可叫集合、总览办中桶全部只读同一
  `replay` 结果，同源同命运。
- 联动同刷：叫号回执（含 `次序证据`：事件号/期望号牌/叫到号牌）、等候墙分栏出队与
  「窗口下一号」、叫号事件、窗口可办列、位次物化、总览办理中桶同源同事务；叫号事务
  `BEGIN IMMEDIATE` + 条件更新，并发双叫不抢同号、不留半截占窗。
- 位次物化：按「当日+种类」全状态取最大位次+1，叫走后新号不撞位次。
- 旧库收敛：升级后对**完全没有审计事件**的号牌补「取号」锚点与「历史」基线（幂等）；
  基线在墙/总览显式标为**补录**、绝不冒充按序叫号；有事件却半截的保持原样由次序闸拒绝。

关键端点：`POST /api/叫号`（仅窗口编号，返回回执与 `次序证据`）、`GET /api/窗口/{id}/下一号`（预览，与叫号同一谓词）、
`GET /api/等候墙`（含窗口下一号、叫号次序、次序审计）、`GET /api/可叫集合`（各窗口可叫下一号 + 全局等候次序）、
`GET /api/叫号流水/校验`（重放校验，含冲突与补录明细）。

测试：`cd backend && python -m pytest tests/`（20 例覆盖 FIFO、并列破、不积压、
并发双叫、位次、回执与快照、重放校验及篡改检出、跳号整笔回滚、墙高亮↔审计↔谓词一致、
序号页次序、总览桶真值、种子自闭合）。

> 范围说明：本口径只覆盖跨种类选号次序；独占并叫与号段游标另立需求。
